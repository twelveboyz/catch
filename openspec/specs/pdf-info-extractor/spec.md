# Spec: PDF Info Extractor

## Overview

从集中流程管理系统的PDF文件中提取项目关键信息，用于自动化填充Excel统计表格。

## Context

该能力服务于CMDB统计功能，用于从用户项目目录下的"1、订购评审纪要"目录中查找PDF文件，并提取申请人、需求方、OA发文时间、主账号等字段。

## REQUIREMENTS

### PDF-001: PDF文件定位

**描述**：系统必须在用户输入目录的"1、订购评审纪要"子目录下自动查找PDF文件。

**验收标准**：
- [ ] 当 `1、订购评审纪要` 目录不存在时，返回明确的错误信息
- [ ] 支持两种PDF命名模式的优先级匹配：
  1. 文件名包含"集中流程管理系统"
  2. 文件名匹配正则 `[A-Z]\d{3}`（如 `E020.pdf`、`E036_集中运维平台...`）
- [ ] 当存在多个匹配的PDF文件时，优先选择包含"集中流程管理系统"的文件
- [ ] 当找不到PDF文件时，返回错误而非崩溃

**测试场景**：
- 正常：PDF文件存在于 `1、订购评审纪要` 目录
- 异常：目录不存在
- 异常：目录存在但无PDF文件
- 边界：多个PDF文件，选择正确的文件

### PDF-002: PDF文本提取

**描述**：系统必须使用 `tools/pdftotext.exe` 工具将PDF内容转换为文本。

**验收标准**：
- [ ] 使用命令 `pdftotext.exe -nopgbrk -raw <source> <dest>` 执行转换
- [ ] 转换后的文本文件保存为临时文件
- [ ] PDF转换失败时返回错误信息
- [ ] 转换成功后返回文本内容

**测试场景**：
- 正常：PDF文件可以正常转换
- 异常：PDF文件损坏或密码保护

### PDF-003: 申请人提取

**描述**：系统必须从PDF文本中提取申请人姓名。

**验收标准**：
- [ ] 使用正则 `申请人：\s*(\p{Han}+)` 匹配申请人字段
- [ ] 提取结果为纯中文姓名（如"黄昌焕"）
- [ ] 当字段不存在时返回空字符串
- [ ] 字段值去除前后空白字符

**测试场景**：
- 正常：`申请人： 黄昌焕` → `黄昌焕`
- 边界：`申请人：黄昌焕`（无空格）→ `黄昌焕`
- 异常：字段不存在 → `""`

### PDF-004: 需求方提取

**描述**：系统必须从PDF文本中提取需求方信息，并去除"X_"前缀。

**验收标准**：
- [ ] 使用正则 `所属独立业务X：\s*X_(.+)` 匹配需求方字段
- [ ] 提取结果去除"X_"前缀（如 `X_研发管理平台` → `研发管理平台`）
- [ ] 当字段不存在时返回空字符串
- [ ] 字段值去除前后空白字符

**测试场景**：
- 正常：`所属独立业务X： X_研发管理平台` → `研发管理平台`
- 边界：包含下划线的需求方名称正确处理
- 异常：字段不存在 → `""`

### PDF-005: OA发文时间提取

**描述**：系统必须从PDF文本中提取"公有云资源订购部署信息接收"的创建时间（日期部分）。

**验收标准**：
- [ ] 使用正则 `公有云资源订购部署信息接收.*?(\d{4}-\d{2}-\d{2})` 匹配日期
- [ ] 提取结果为格式 `YYYY-MM-DD`（如 `2026-01-19`）
- [ ] 忽略时间部分（如 `2026-01-19 22:41:29` 只提取 `2026-01-19`）
- [ ] 当字段不存在时返回空字符串

**测试场景**：
- 正常：`公有云资源订购部署信息接收 2026-01-19 22:41:29` → `2026-01-19`
- 边界：日期格式变体（如 `2026/01/19`）
- 异常：字段不存在 → `""`

### PDF-006: 主账号提取

**描述**：系统必须从PDF文本中提取订购账号（主账号）。

**验收标准**：
- [ ] 使用正则 `订购帐号：\s*(\w+)` 匹配订购账号字段
- [ ] 提取结果为账号字符串（如 `cmic_jsglpt`）
- [ ] 当字段不存在时返回空字符串
- [ ] 字段值去除前后空白字符

**测试场景**：
- 正常：`订购帐号： cmic_jsglpt` → `cmic_jsglpt`
- 边界：包含特殊字符的账号（如 `cmic-jsglpt`）
- 异常：字段不存在 → `""`

### PDF-007: 错误处理与日志

**描述**：系统必须在各个阶段提供清晰的错误信息和日志。

**验收标准**：
- [ ] PDF文件未找到时，记录 `Warn` 级别日志，说明具体原因
- [ ] PDF转换失败时，记录 `Error` 级别日志，包含错误详情
- [ ] 字段提取失败时，记录 `Debug` 级别日志
- [ ] 所有错误必须向上传播，由调用者决定降级策略

**测试场景**：
- 各种异常情况下的日志输出验证
- 日志级别符合规范

### PDF-008: 接口设计

**描述**：系统必须提供清晰、易用的API接口。

**验收标准**：
- [ ] 主函数签名：`ExtractFromPDF(root string) (*PdfInfo, error)`
- [ ] `PdfInfo` 结构体包含：`Applicant`, `DemandSide`, `OAPublishTime`, `PrimaryAccount`
- [ ] 所有字符串字段为空时表示提取失败
- [ ] 错误信息清晰，包含失败原因

**接口定义**：
```go
type PdfInfo struct {
    Applicant     string // 申请人
    DemandSide    string // 需求方
    OAPublishTime string // OA发文时间
    PrimaryAccount string // 主账号
}

// ExtractFromPDF 从项目目录下的"1、订购评审纪要"目录中查找PDF并提取信息
func ExtractFromPDF(root string) (*PdfInfo, error)
```

## Non-Functional Requirements

### 性能
- PDF转换和提取应在 5 秒内完成（针对常规大小的PDF文件）

### 可维护性
- 正则表达式必须集中定义，便于维护和调整
- 每个字段提取函数必须独立，便于单元测试

### 兼容性
- 必须兼容 Windows 环境（项目主要运行平台）
- 必须使用现有的 `tools/pdftotext.exe` 工具
